Variables : let, const, var

const

Empêche la réaffectation et possède une portée de bloc. Le contenu d’un objet ou d’un tableau reste modifiable.

const PI = 3.14; 
// PI = 3.1415; <-- ERREUR

let

Déclare une variable avec une portée de bloc ({}). PEUT être réassignée. 

let compteur = 0;
compteur = 1;     // OK

var (À ÉVITER)

Possède une portée de fonction, pas de bloc. Préférez let et const dans le nouveau code.

if (true) {
  var x = 10;
}
// console.log(x); // 10 (Fuite hors du bloc)

⭐ Règle d'or : Toujours utiliser const par défaut. Si vous devez réassigner, utilisez let.

Opérateurs de Comparaison

Double Égal (==) - Comparaison Lâche (Loose)

Compare la valeur en effectuant une conversion de type implicite. 

console.log(1 == '1');   // true
console.log(0 == false); // true
console.log(null == undefined); // true

Triple Égal (===) - Comparaison Stricte

Compare sans conversion de type. Préférez === et !== pour des comparaisons prévisibles.

console.log(1 === '1');   // false
console.log(0 === false); // false
console.log(null === undefined); // false

Autres :

  • Arithmétiques : +, -, *, /, % (reste), ** (puissance).
  • Logiques : && (ET), || (OU), ! (NON).
  • Ternaire : condition ? vrai : faux; (pour les conditions simples).

Structures Conditionnelles

if / else if / else

La condition est convertie en booléen. false, 0, "", null, undefined et NaN sont notamment falsy ; [] et {} sont truthy.

const note = 85;
if (note > 90) {
  console.log("A");
} else if (note > 80) {
  console.log("B"); // C'est ici
} else {
  console.log("C");
}

switch / case

Pour vérifier si une variable correspond à plusieurs valeurs spécifiques. 

const jour = 'Lundi';
switch (jour) {
  case 'Samedi':
  case 'Dimanche':
    console.log("WE");
    break;
  default:
    console.log("Semaine");
}

Utilisez switch quand vous comparez une seule valeur à plusieurs constantes. Sinon, utilisez if/else.

Boucles : for, while

La boucle for (itération par index) 

// 1. Initialisation (let i = 0)
// 2. Condition de continuation (i < 5)
// 3. Incrémentation (i++)
for (let i = 0; i < 5; i++) {
  console.log("Tour " + i);
}

Boucles while et do...while 

// while : la condition est vérifiée avant chaque tour
let x = 0;
while (x < 3) {
  console.log("x est : " + x);
  x++;
}

// do...while : s'exécute au moins une fois
let y = 0;
do {
  console.log("y est : " + y);
} while (y > 0); // La boucle s'arrête après 1 tour

Boucles : for...of et for...in

for...of (Valeurs)

Itère sur les VALEURS d'objets itérables (tableaux, chaînes de caractères, etc.). 

const couleurs = ['rouge', 'vert', 'bleu'];
for (const couleur of couleurs) {
  console.log(couleur);
}
// Affiche : rouge, vert, bleu

for...in (Clés/Index)

Parcourt les propriétés énumérables à clé texte, y compris celles héritées. Pour les propriétés propres, préférez Object.keys() ou Object.entries().

const voiture = { marque: 'BMW', annee: 2020 };
for (const cle in voiture) {
  console.log(cle + ' : ' + voiture[cle]);
}
// Affiche : marque : BMW, annee : 2020

Contrôle :

for (let i = 0; i < 10; i++) {
  if (i === 3) continue; // Passe au tour suivant
  if (i === 7) break;    // Arrête la boucle
  console.log(i);
}

Fonctions

Déclaration Classique

Blocs de code réutilisables qui peuvent prendre des paramètres et retourner une valeur (return).

  const resultat = a + b;
  return resultat;
  // Rien après return n'est exécuté
}

const somme = addition(5, 3); // 8
const unDePlus = addition(10); // 11 (b utilise sa valeur par défaut)

Fonctions Anonymes

Fonctions : Fléchées & Portée (Scope)

Fonctions Fléchées (Arrow Functions) - ES6

Syntaxe concise. N'a pas son propre this (très important en React). 

// Longue
const multiplication = (a, b) => {
  return a * b;
};

// Courte (return implicite pour une seule expression)
const carre = n => n * n;

Portée (Scope) des Variables

La portée détermine où une variable est accessible. let et const sont limitées au bloc qui les contient ; une fonction peut lire les variables de sa portée extérieure.

const globalVar = 'Globale';
function maFonction() {
  const localVar = 'Locale'; // Inaccessible à l'extérieur
  console.log(globalVar); 
}

Tableaux (Arrays)

Création et Accès

Les tableaux sont des listes ordonnées d'éléments (indexés à partir de 0). 

const legumes = ['carotte', 'tomate', 'oignon'];

console.log(legumes[0]);   // Accès : 'carotte'
console.log(legumes.length); // Propriété : 3

Mutations (Modification du tableau original)

  • push(e) : Ajoute un élément à la fin.
  • pop() : Retire le dernier élément.
  • unshift(e) : Ajoute un élément au début.
  • shift() : Retire le premier élément.
legumes.push('pomme de terre'); // ['carotte', ..., 'pomme de terre']

Tableaux : Méthodes de Transformation

map et filter créent un tableau ; reduce calcule une valeur. Ces méthodes ne mutent pas directement le tableau : évitez aussi de modifier les éléments dans leurs callbacks.

.map()

Crée un nouveau tableau en appliquant une fonction à chaque élément. 

[1, 2].map(n => n * 2); 
// [2, 4]

.filter()

Crée un nouveau tableau avec les éléments qui passent un test (retournent true). 

[1, 2, 3].filter(n => n > 1);
// [2, 3]

.reduce()

Exécute une fonction sur chaque élément pour produire une seule valeur (accumulateur). 

[1, 2, 3].reduce((acc, n) => acc + n, 0); 
// 6

Objets

Création et Accès

Un objet regroupe des propriétés : chaque clé (texte ou symbole) est associée à une valeur. Pour une liste ordonnée d’éléments, utilisez un tableau.

const utilisateur = {
  nom: 'Dupont',
  age: 25,
  estActif: true,
  saluer: function() { return 'Bonjour ' + this.nom; }
};

// Accès 1 (dot notation)
console.log(utilisateur.nom);  // 'Dupont'

// Accès 2 (bracket notation, utile pour les clés dynamiques)
console.log(utilisateur['age']); // 25

Modification / Suppression 

utilisateur.age = 26; // Modifier
delete utilisateur.estActif; // Supprimer

Objets : Méthodes Utiles & Destructuring

Méthodes de Parcours 

Object.keys(utilisateur);   // ['nom', 'age', 'saluer']
Object.values(utilisateur); // ['Dupont', 26, function...]
Object.entries(utilisateur); // [['nom', 'Dupont'], ['age', 26], ...]

Déstructuration (destructuring) — ES2015

Extrait des valeurs d'un objet ou d'un tableau en variables distinctes. 

const { nom, age } = utilisateur;
console.log(nom); // 'Dupont'
console.log(age); // 26

const [premiere, ...reste] = [1, 2, 3];
console.log(premiere); // 1

Classes en JavaScript

Une classe est un modèle pour créer des objets partageant des propriétés et des méthodes. 

class Utilisateur {
  constructor(nom) {
    this.nom = nom;
  }

  saluer() {
    return `Bonjour ${this.nom}`;
  }
}

const user = new Utilisateur('Alice');
console.log(user.saluer()); // Bonjour Alice
  • constructor initialise l'instance.
  • new crée un objet à partir de la classe.
  • Les méthodes décrivent les comportements de l'objet.

Classes : héritage et réutilisation

extends permet de réutiliser une classe existante ; super() appelle son constructeur. 

class Admin extends Utilisateur {
  constructor(nom, role) {
    super(nom);
    this.role = role;
  }

  afficherRole() {
    return `${this.nom} : ${this.role}`;
  }
}

const admin = new Admin('Samir', 'formateur');

Les classes rendent le code objet plus lisible, tout en reposant sur les prototypes de JavaScript.

Événements : addEventListener

Qu'est-ce qu'un événement ?

Une action du navigateur ou de l'utilisateur (clic, survol, chargement, soumission de formulaire, touche enfoncée).

Attacher un écouteur 

// HTML : <form id="inscription">…</form>
const formulaire = document.querySelector('#inscription');
if (formulaire) {
  formulaire.addEventListener('submit', function (event) {
    event.preventDefault(); // évite l'envoi HTML et le rechargement
    console.log('Formulaire soumis');
  });
}
  • Types fréquents : click, submit, change, input, mouseover, keydown.

Événements : Propagation & Délégation

Propagation (Bubbling)

Un événement qui remonte, comme click, passe de sa cible à ses ancêtres. Tous les événements ne remontent pas : focus, par exemple, ne le fait pas.

Délégation d'Événements

Attacher un seul écouteur à un élément parent pour gérer les événements de tous ses enfants (même ceux ajoutés dynamiquement). 

const liste = document.querySelector('#ma-liste');
if (liste) {
  liste.addEventListener('click', event => {
    if (!(event.target instanceof Element)) return;
    const item = event.target.closest('li');
    if (item && liste.contains(item)) {
      console.log('Élément cliqué :', item.textContent);
    }
  });
}
// closest() gère aussi un clic sur un élément à l'intérieur du li.

ES6+ : écrire un JavaScript plus moderne

Template literals

Les backticks permettent d'insérer des expressions avec ${} et d'écrire du texte sur plusieurs lignes.

const nom = "Bob";
const age = 25;
const message = `Salut ${nom} !
Tu as ${age} ans.`;

Paramètres par défaut

Une valeur par défaut s’applique si la valeur manque ou vaut undefined, mais pas si elle vaut null.

function afficher({ nom, age = 18 }) {
  return `${nom} a ${age} ans`;
}
afficher({ nom: 'Lina' });
// Lina a 18 ans

Ces syntaxes réduisent le code répétitif et rendent l'intention plus claire.

ES6+ : spread, rest et copie superficielle

Spread (...) : copier

Le spread décompose un tableau ou un objet. Il permet de créer une nouvelle valeur sans modifier l'originale.

const nombres = [1, 2];
const tous = [...nombres, 3];
const copie = [...nombres];

const user = { nom: 'Ali', actif: true };
const admin = { ...user, role: 'admin' };

Rest (...) : regrouper

Le rest rassemble les valeurs restantes dans un tableau ou un objet.

// math.js
function additionner(...nombres) {
  return nombres.reduce((total, n) => total + n, 0);
}

additionner(2, 3, 5); // 10

Le spread copie un seul niveau : les objets imbriqués restent partagés. Pour modifier une propriété imbriquée sans mutation, copiez chaque niveau concerné.

Modules : organiser le projet

Un module est un fichier JavaScript avec son propre espace de noms. Seules les valeurs exportées peuvent être utilisées par les autres fichiers.

Exporter

// math.js
export const PI = 3.14;

export function additionner(a, b) {
  return a + b;
}

export default function saluer(nom) {
  return `Bonjour ${nom}`;
}

Importer

// app.js
import saluer, { PI, additionner } from './math.js';

console.log(PI);                // 3.14
console.log(additionner(2, 3)); // 5
console.log(saluer('Lina'));
  • Export nommé : importé entre accolades ; import { PI as pi } permet de le renommer.
  • Export par défaut : un seul par fichier ; le nom d'import peut changer.
  • Chemin relatif : ./ désigne le dossier actuel et ../ le dossier parent.

Dans le navigateur, chargez l’entrée avec <script type="module" src="app.js"></script> et servez les fichiers via HTTP. Vite s’en occupera dans le projet React.

Modules : utiliser une fonction importée

Séparons le calcul et l’affichage dans un exemple JavaScript exécutable. La même organisation sera utilisée dans React.

// userUtils.js
export const getActiveUsers = users =>
  users.filter(user => user.active);

// app.js

  { name: 'Lina', active: true },
  { name: 'Omar', active: false }
];
console.log(getActiveUsers(users));
// [{ name: 'Lina', active: true }]

Une fonction pure reçoit des données et retourne un résultat. Elle peut être réutilisée et testée sans dépendre de l’interface.

Asynchrone : comprendre l’ordre d’exécution

Le code synchrone s’exécute sur la pile d’appels. Le navigateur gère les minuteurs et le réseau ; leurs callbacks attendent que la pile soit libre.

console.log('1. Début');
setTimeout(() => console.log('4. Minuteur'), 0);
Promise.resolve().then(() => console.log('3. Promesse'));
console.log('2. Fin du code synchrone');
  • Les callbacks de promesses passent dans la file des microtâches, avant la tâche suivante du minuteur.
  • setTimeout(..., 0) ne signifie pas « immédiatement ». Un long calcul synchrone peut toujours bloquer l’interface.
  • Un callback est une fonction passée à une autre fonction : il peut être synchrone (map) ou asynchrone (minuteur).

Promesses : enchaîner un résultat ou une erreur

Une promesse est pending, puis fulfilled ou rejected. then transforme le résultat ; catch traite un échec.

fetch('/api/users')
  .then(response => {
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return response.json();
  })
  .then(users => console.log(users))
  .catch(error => console.error('Chargement impossible :', error))
  .finally(() => console.log('Requête terminée'));

fetch ne rejette pas automatiquement une réponse HTTP 404 ou 500 : vérifiez response.ok. Ici, /api/users suppose un serveur qui expose cette route.

async / await : garder les erreurs visibles

Une fonction async retourne une promesse. await suspend cette fonction, sans bloquer tout JavaScript.

async function getJson(url) {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}

async function chargerPage() {
  try {
    const [users, products] = await Promise.all([
      getJson('/api/users'), getJson('/api/products')
    ]);
    console.log(users, products);
  } catch (error) {
    console.error('Chargement impossible :', error.message);
  }
}
chargerPage();

Promise.all regroupe des opérations indépendantes. Si une promesse rejette, l’ensemble rejette ; les autres opérations ne sont pas automatiquement annulées.

PARTIE 2 : NODE.JS

Exécuter JavaScript, utiliser npm et créer des scripts

Node.js : JavaScript en dehors du navigateur

Node.js permet d'exécuter JavaScript en dehors du navigateur, directement sur votre ordinateur ou sur un serveur.

Pourquoi Node.js ?

  • Exécuter des programmes JavaScript depuis le terminal.
  • Utiliser npm, le gestionnaire de paquets JavaScript.
  • Créer des scripts, des serveurs et des outils en ligne de commande.
  • Gérer les dépendances et les scripts d'un projet.

Navigateur vs Node.js

Le navigateur fournit le DOM et document. Node.js fournit le système de fichiers, le terminal et les outils serveur.

// navigateur
document.querySelector('h1');

// Node.js
console.log('Exécuté dans le terminal');

Installer Node.js et vérifier l'installation

  1. Télécharger la version LTS sur nodejs.org et vérifier sa compatibilité avec la version de Vite utilisée.
  2. Exécuter l'installateur et conserver les options par défaut.
  3. Fermer puis rouvrir le terminal pour recharger le chemin système.

Vérifier les versions

node --version
npm --version
# Les numéros dépendent de la version LTS installée.

Node.js installe généralement npm en même temps. Si une commande n'est pas reconnue, redémarrez le terminal ou vérifiez l'installation.

npm : le gestionnaire de paquets Node.js

npm est un gestionnaire de paquets JavaScript. Sa commande permet d’installer, mettre à jour ou supprimer des dépendances, et de lancer les scripts du projet.

Commandes essentielles

npm init -y          # créer package.json
npm install          # installer les dépendances
npm install lodash   # ajouter un paquet
npm uninstall lodash # supprimer un paquet
npm run start        # lancer un script

Le registre npm

npm cherche les paquets dans le registre public. Chaque paquet contient du code réutilisable : bibliothèques, outils, plugins ou frameworks.

npm view lodash version
npm search date
npm outdated

npm automatise la gestion des dépendances : les versions sont enregistrées pour pouvoir reconstruire le projet.

package.json : la carte d'identité du projet

Ce fichier décrit le projet, ses commandes et les paquets dont il a besoin. Il est versionné avec le code et ne doit pas être supprimé.

{
  "name": "demo-node",
  "version": "1.0.0",
  "main": "app.js",
  "scripts": {
    "start": "node app.js",
    "test": "node --test"
  },
  "dependencies": {
    "lodash": "^4.17.21"
  },
  "devDependencies": {
    "nodemon": "^3.0.0"
  }
}
  • dependencies : paquets nécessaires pour exécuter l'application.
  • devDependencies : outils de développement, de test et de build ; nécessaires pour construire l’application, même si le site livré ne les exécute pas.
  • scripts : raccourcis comme npm run start ou npm test.

node_modules et package-lock.json

node_modules/

Dossier qui contient le code réel des paquets installés et leurs propres dépendances.

  • Il peut devenir très volumineux.
  • On ne le commit généralement pas dans Git.
  • On le recrée avec npm ci lorsque le fichier de verrouillage est présent et cohérent.

package-lock.json

npm y enregistre les versions exactes installées et l'arbre complet des dépendances.

# après avoir cloné un projet avec son lockfile
npm ci
# recrée node_modules selon les versions verrouillées
# échoue si package.json et le lockfile divergent

Règle importante : partager package.json et package-lock.json, mais ignorer node_modules.

Installer, mettre à jour et supprimer un paquet

# dépendance utilisée par l'application
npm install lodash

# outil uniquement pour le développement
npm install --save-dev nodemon

# mettre à jour selon package.json
npm update lodash

# supprimer un paquet et son entrée dans package.json
npm uninstall lodash

Quels fichiers changent ?

install et uninstall enregistrent les dépendances dans le manifeste et le lockfile. update actualise les versions autorisées ; npm ci ne réécrit aucun de ces deux fichiers.

# voir les paquets installés
npm list --depth=0

# réinstaller proprement selon le lock
npm ci

npm ci est utile dans les pipelines de test et de déploiement, car il installe exactement les versions verrouillées.

JSX décrit l’interface avec une syntaxe proche de HTML, directement dans JavaScript. Vite transforme le JSX avant son exécution dans le navigateur.

Repère : classes — cycle de vie et événements

Un composant de classe passe par trois moments : montage (création), mise à jour (props ou state changent), puis démontage (retrait de l’interface).

Un exemple complet

class Horloge extends React.Component {
  state = { secondes: 0 };

  componentDidMount() {
    // Après l’affichage initial
    this.timer = setInterval(() => {
      this.setState(prev => ({
        secondes: prev.secondes + 1
      }));
    }, 1000);
  }

  componentDidUpdate(prevProps, prevState) {
    if (prevState.secondes !== this.state.secondes) {
      document.title = `${this.state.secondes}s`;
    }
  }

  componentWillUnmount() {
    // Avant le retrait : arrêter le timer
    clearInterval(this.timer);
  }

  render() {
    return <p>{this.state.secondes} s</p>;
  }
}

Que fait chaque méthode ?

  • componentDidMount s’exécute une fois après le premier rendu. On y démarre un abonnement, un timer ou une requête.
  • componentDidUpdate s’exécute après une mise à jour. Comparez les anciennes valeurs avant de modifier le state ou le document.
  • componentWillUnmount nettoie ce qui a été démarré : timer, abonnement ou écouteur d’événement.

Attention à this

Quand React appelle une méthode comme gestionnaire, this peut être perdu. Une propriété fléchée lie automatiquement le contexte ; sinon utilisez bind dans le constructeur.

handleClick = () => {
  this.setState({ ouvert: true });
};

// Alternative dans constructor :
this.handleClick = this.handleClick.bind(this);

À retenir : chaque ressource ouverte dans componentDidMount doit être fermée dans componentWillUnmount. Les composants fonctionnels utilisent plutôt useEffect avec une fonction de nettoyage.

State (État) : Le Hook useState

Qu'est-ce que l'État ?

L’état est la mémoire du composant entre les rendus. Une mise à jour demande à React un nouveau rendu ; le DOM ne change que si le résultat affiché change.

useState Hook :

  • Retourne une paire : [valeurActuelle, fonctionDeMiseÀJour].
  • useState retourne [valeur, setter]. Le setter prépare la valeur du prochain rendu : la variable du rendu en cours ne change pas immédiatement.
import { useState } from 'react';

function Toggle() {
  const [isOn, setIsOn] = useState(false); // Valeur initiale: false

  const handleToggle = () => {
    // Utilisez une fonction de mise à jour pour des dépendances sûres
    setIsOn(prevIsOn => !prevIsOn);
  };

  return (
    <button onClick={handleToggle}>
      {isOn ? 'ON' : 'OFF'}
    </button>
  );
}

State : calculer depuis la valeur précédente

Chaque rendu voit un instantané de l’état. React peut regrouper plusieurs mises à jour : utilisez une fonction lorsque la prochaine valeur dépend de la précédente.

// Dans un composant :
const [count, setCount] = useState(0);

function ajouterTrois() {
  setCount(c => c + 1);
  setCount(c => c + 1);
  setCount(c => c + 1); // +3 au prochain rendu
}
// Trois appels à setCount(count + 1) demanderaient
// trois fois la même valeur : seulement +1.

Le setter ne renvoie pas une promesse : await setCount(...) n’attend pas le rendu. Les fonctions de mise à jour doivent rester pures.

State : modifier sans mutation

Avec useState, remplacez les objets et tableaux au lieu de les modifier. Le spread est une copie superficielle : copiez chaque niveau modifié.

const [profil, setProfil] = useState({
  nom: 'Lina', adresse: { ville: 'Rabat' }
});

function changerVille(ville) {
  setProfil(p => ({
    ...p, adresse: { ...p.adresse, ville }
  }));
}

const [items, setItems] = useState([]);
const ajouter = item => setItems(liste => [...liste, item]);
const supprimer = id => setItems(liste =>
  liste.filter(item => item.id !== id)
);

Évitez profil.adresse.ville = … et items.push(…) sur le state. La syntaxe de mutation d’Immer sera un cas particulier présenté avec Redux Toolkit.

useEffect : synchroniser avec un système externe

Un effet synchronise React avec un minuteur, un abonnement ou une API du navigateur. Les calculs dérivés restent dans le rendu ; les actions utilisateur restent dans les gestionnaires d’événements.

import { useEffect } from 'react';

function TitrePage({ titre }) {
  useEffect(() => {
    document.title = titre;
  }, [titre]);
  return <h1>{titre}</h1>;
}
  • Sans tableau : après chaque commit. Avec [] : à chaque montage. Avec [titre] : au montage et lorsque titre change.
  • Incluez toutes les valeurs réactives lues dans l’effet. Ne supprimez pas une dépendance pour forcer son exécution.
  • En développement, StrictMode ajoute un cycle installation → nettoyage → installation pour détecter les défauts.

useEffect : La Fonction de Nettoyage (Cleanup)

Pourquoi ?

Pour annuler ou nettoyer les effets qui persistent après que le composant ait été retiré du DOM (démontage) ou avant que l'effet ne s'exécute à nouveau.

Exemple : Timer

useEffect(() => {
  const timer = setInterval(() => {
    console.log('Tick');
  }, 1000);

  // Fonction de nettoyage
  return () => {
    clearInterval(timer); // Arrête le timer
    console.log("Cleanup effectuée");
  };
}, []);

Retournez un nettoyage quand l’effet ouvre une ressource ou un abonnement. Il s’exécute avant une nouvelle installation avec des dépendances modifiées et au démontage ; tous les effets n’en ont pas besoin.

L’API Context distribue une valeur aux descendants sans la transmettre par props à chaque niveau. Elle ne stocke pas l’état à elle seule : combinez-la avec useState ou useReducer si la valeur doit évoluer.

  • Le thème (clair/sombre)
  • L’utilisateur connecté
  • Les paramètres de langue
  • Le panier dans une boutique

Hook useRef()

Qu’est-ce que useRef ?

useRef() permet de stocker une valeur persistante entre les rendus sans provoquer de nouveau rendu.

Exemple : accéder à un élément DOM 

import { useRef } from 'react';

  const inputRef = useRef(null);
  return (
    <div>

      <input id="recherche" ref={inputRef} />

      </button>

Hook useReducer : gérer des états complexes

useReducer est une alternative à useState pour les états plus complexes (objets, multiples sous-valeurs) ou avec beaucoup de transitions.

  • Basé sur le pattern state + action → nouveau state.
  • Ressemble beaucoup à Redux (même logique de reducer).
import { useReducer } from "react";

function reducer(state, action) {
  switch (action.type) {
    case "increment":
      return { count: state.count + 1 };
    case "decrement":
      return { count: state.count - 1 };
    case "reset":
      return { count: 0 };
    default:
      return state;
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });

  return (
    <div>
      <p>Compteur : {state.count}</p>
      <button onClick={() => dispatch({ type: "increment" })}>+</button>
      <button onClick={() => dispatch({ type: "decrement" })}>-</button>
      <button onClick={() => dispatch({ type: "reset" })}>Reset</button>
    </div>
  );
}

Très utile pour des formulaires complexes, des wizards, ou des composants avec beaucoup de règles métier.

Un reducer reste pur : pas de requête réseau, de mutation du state reçu, ni d’effet de bord. dispatch décrit une transition avec une action.

Custom Hooks : réutiliser la logique

Un custom hook est une fonction qui commence par use... et qui permet de factoriser de la logique React (state, effets, contexte) pour la réutiliser dans plusieurs composants.

  • Permet d’éviter les duplications (DRY).
  • Peut combiner plusieurs hooks internes (useState, useEffect…).

Exemple : hook useToggle 

import { useState } from "react";

function useToggle(initialValue = false) {
  const [value, setValue] = useState(initialValue);
  const toggle = () => setValue((prev) => !prev);
  return { value, toggle };
}

// Utilisation
function Switch() {
  const { value: isOn, toggle } = useToggle();

  return (
    <button onClick={toggle}>
      {isOn ? "ON" : "OFF"}
    </button>
  );
}

Un custom Hook partage la logique, pas automatiquement l’état : deux appels à useToggle() créent deux états indépendants.

PARTIE 6 : REDUX PRATIQUE

État global, Redux classique, Toolkit et custom hooks

Pourquoi l'état global devient un problème ?

Un état est global lorsqu'il doit être lu ou modifié par plusieurs composants éloignés dans l'application.

Exemples

  • Utilisateur connecté et permissions.
  • Panier et nombre d'articles.
  • Thème clair/sombre.
  • Notifications et messages non lus.

Sans organisation

Chaque composant peut garder sa propre copie. Une modification dans un endroit peut alors ne pas être reflétée ailleurs.

Navbar : user = "Lina"
Profile : user = "Lina"
Cart    : user = "Lina"
// Plusieurs copies à synchroniser

Le problème n'est pas useState : c'est le partage et la synchronisation d'une même donnée.

Le prop drilling : faire passer des données trop loin

Le prop drilling arrive lorsqu'une donnée doit traverser plusieurs composants intermédiaires qui ne l'utilisent pas, uniquement pour atteindre un composant final.

function App() {
  const user = { name: 'Lina' };
  return <Layout user={user} />;
}

function Layout({ user }) {
  return <Header user={user} />;
}

function Header({ user }) {
  return <UserMenu user={user} />;
}

function UserMenu({ user }) {
  return <span>Bonjour {user.name}</span>;
}

Couplage

Les composants intermédiaires connaissent des données qui ne les concernent pas.

Maintenance

Ajouter une nouvelle donnée oblige à modifier toute la chaîne.

Lisibilité

Il devient difficile de savoir qui possède et modifie la donnée.

Ce que Redux corrige

Redux place l'état partagé dans un store unique. Les composants lisent ce store et demandent un changement en envoyant une action.

Store

une source unique

Action

une intention

Reducer

une transition prévisible

UI

mise à jour automatique

const count = useSelector(state => state.counter.value);
const dispatch = useDispatch();

// Le composant ne modifie pas le store directement
dispatch({ type: 'counter/increment' });
  • Centralisation : une seule valeur partagée au lieu de copies concurrentes.
  • Traçabilité : chaque modification correspond à une action identifiable.
  • Prévisibilité : les reducers décrivent comment l'état peut évoluer.

Redux est utile pour un état partagé avec de nombreuses transitions et un besoin de traçabilité. Un menu ouvert peut rester local ; un thème peut souvent utiliser Context.

Redux classique : comprendre le flux

Redux est une bibliothèque qui centralise l'état de l'application dans un store. Les composants ne modifient pas directement cet état.

UI

affiche le state

Action

décrit l'intention

Reducer

calcule le nouvel état

Store

conserve le state

const action = { type: 'counter/increment', payload: 1 };

function reducer(state = { count: 0 }, action) {
  if (action.type === 'counter/increment') {
    return { ...state, count: state.count + action.payload };
  }
  return state;
}

Flux unidirectionnel : UI → dispatch(action) → reducer → nouveau state → UI.

Redux classique : créer le store et le reducer

Le store contient l'état global. dispatch() envoie une action ; getState() lit l'état ; subscribe() réagit à ses changements.

import { createStore } from 'redux';

const initialState = { count: 0 };

function counterReducer(state = initialState, action) {
  switch (action.type) {
    case 'INCREMENT':
      return { ...state, count: state.count + 1 };
    case 'ADD':
      return { ...state, count: state.count + action.payload };
    case 'RESET':
      return initialState;
    default:
      return state;
  }
}

const store = createStore(counterReducer);
store.dispatch({ type: 'ADD', payload: 5 });
console.log(store.getState()); // { count: 5 }
  • Le reducer ne modifie jamais directement state : il retourne un nouvel objet.
  • Le switch associe chaque type d'action à une transition d'état.
  • Une action ne fait rien seule : elle doit être envoyée avec dispatch().

Exemple historique : il nécessite npm install redux react-redux. createStore est déprécié pour le nouveau code ; préférez configureStore de Redux Toolkit.

Le package react-redux fournit Provider pour rendre le store disponible et les fonctions useSelector/useDispatch pour le lire et envoyer des actions.

Redux Toolkit : appels API avec createAsyncThunk

createAsyncThunk encapsule une opération asynchrone et génère automatiquement trois actions : pending (en cours), fulfilled (réussite) et rejected (erreur).

import { createAsyncThunk } from '@reduxjs/toolkit';

export const fetchUsers = createAsyncThunk(
  'users/fetchUsers',
  async (_, thunkAPI) => {
    try {
      const response = await fetch('/api/users');
      if (!response.ok) throw new Error('Erreur serveur');
      return await response.json();
    } catch (error) {
      return thunkAPI.rejectWithValue(error.message);
    }
  }
);

Le composant fait seulement dispatch(fetchUsers()). Le thunk gère l'appel réseau et transmet le résultat au slice.

Un thunk ne fournit pas un cache API à lui seul. Pour charger et mettre en cache des données serveur avec Redux, RTK Query est le choix recommandé ; les thunks conviennent à une logique asynchrone personnalisée.

createAsyncThunk : charger, réussir, échouer

// features/users/usersSlice.js
import { createSlice } from '@reduxjs/toolkit';
import { fetchUsers } from './usersThunks';

const usersSlice = createSlice({
  name: 'users',
  initialState: { data: [], status: 'idle', error: null },
  reducers: {},
  extraReducers: builder => {
    builder
      .addCase(fetchUsers.pending, state => {
        state.status = 'loading';
        state.error = null;
      })
      .addCase(fetchUsers.fulfilled, (state, action) => {
        state.status = 'succeeded';
        state.data = action.payload;
      })
      .addCase(fetchUsers.rejected, (state, action) => {
        state.status = 'failed';
        state.error = action.payload || action.error.message;
      });
  }
});
export default usersSlice.reducer;

pending

Afficher un loader.

fulfilled

Afficher les données.

rejected

Afficher un message d'erreur.

Ajoutez le reducer sous la clé users dans configureStore. L’appel réseau appartient au thunk ; le slice réagit à ses actions. Affichez aussi un état vide si data.length === 0.

// hooks/reduxHooks.js
import { useDispatch, useSelector } from 'react-redux';
import { login, logout } from '../features/auth/authSlice';

export const useCurrentUser = () =>
  useSelector(state => state.auth.user);
export const useIsAuthenticated = () =>
  useSelector(state => state.auth.user !== null);

  const dispatch = useDispatch();
  return {
    login: user => dispatch(login(user)),
    logout: () => dispatch(logout())
  };
}

// features/cart/cartSlice.js
import { createSlice } from '@reduxjs/toolkit';

const cartSlice = createSlice({
  name: 'cart',
  initialState: { items: [] },
  reducers: {
    addItem(state, action) {
      const item = state.items.find(i => i.id === action.payload.id);
      if (item) item.quantity += 1;
      else state.items.push({ ...action.payload, quantity: 1 });
    },
    removeItem(state, action) {
      state.items = state.items.filter(i => i.id !== action.payload);
    },
    clearCart(state) { state.items = []; }

Redux pratique : règles pour un projet solide

  • Stocker l'état partagé : auth, panier, filtres globaux, cache API.
  • Garder l'état local : ouverture d'un menu ou valeur temporaire d'un formulaire.
  • Organiser par feature : chaque domaine possède son slice, ses selectors et ses thunks.
  • Utiliser des selectors : un seul endroit pour lire et calculer les données dérivées.
  • Gérer les trois états API : loading, succeeded et failed.
  • Ne pas mettre : fonctions, instances de classes ou éléments DOM dans le store.

PARTIE 7 : APIs & Intégration Back-End

REST, HTTP, JSON, Fetch, Axios & bonnes pratiques

Qu’est-ce qu’une API ? Qu’est-ce qu’une REST API ?

Une API est une interface qu’un programme expose à d’autres programmes. Dans ce chapitre, nous utilisons des API Web pour échanger des données via HTTP.

  • API Web : accessible via HTTP(s), généralement au format JSON.
  • REST : style architectural centré sur des ressources et une interface uniforme ; les requêtes sont sans état côté serveur au sens où chacune contient les informations nécessaires à son traitement. HTTP et JSON ne suffisent pas à eux seuls à définir REST.
  • Une ressource peut être : /users, /orders, /products, etc.

Exemple : GET https://api.example.com/users/42 → récupère l’utilisateur avec l’ID 42.

Verbes HTTP & Codes de Statut

Verbes principaux

  • GET : Lire / récupérer des données.
  • POST : soumettre des données à traiter ; souvent utilisé pour créer une ressource.
  • PUT : Remplacer complètement une ressource.
  • PATCH : Modifier partiellement une ressource.
  • DELETE : Supprimer une ressource.

Codes de statut HTTP (réponse serveur)

  • 2xx : succès — 200 OK, 201 Created, 204 No Content (sans corps).
  • 4xx : problème de requête — 400 invalide, 401 authentification requise ou invalide, 403 accès refusé, 404 introuvable.
  • 5xx : Erreur côté serveur (500 Internal Server Error).

Vérifiez le statut et le format attendu. Une réponse 204 n’a pas de corps : n’appelez pas response.json() dessus.

Endpoints, Headers, Body & JSON

1️⃣ Endpoint

URL d’un service précis, par exemple : https://api.example.com/users?page=2.

2️⃣ Headers

Métadonnées envoyées avec la requête/réponse :

  • Content-Type: application/json
  • Authorization: Bearer <token>

3️⃣ Body (corps)

Données envoyées dans une requête (POST/PUT/PATCH), souvent en JSON. 

{
  "name": "Alice",
  "email": "alice@example.com"
}

JSON utilise des clés entre guillemets doubles. JSON.stringify(objet) sérialise un objet ; JSON.parse(texte) lit du JSON. Il n’accepte ni fonctions, ni commentaires, ni virgule finale.

Envoyer du JSON avec fetch

async function creerArticle() {
  try {
    const response = await fetch(
      'https://jsonplaceholder.typicode.com/posts',
      {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ title: 'Bonjour', body: 'React', userId: 1 })
      }
    );
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const article = await response.json();
    console.log(article);
  } catch (error) {
    console.error('Enregistrement impossible :', error.message);
  }
}

Appelez cette fonction depuis un événement de soumission. JSONPlaceholder simule l’écriture : les données ne sont pas enregistrées durablement.

Intégrer une API avec fetch()

fetch est l’API native du navigateur pour faire des requêtes HTTP.

Exemple : GET + gestion du chargement / erreur 

import { useEffect, useState } from 'react';

function Users() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    async function loadUsers() {
      try {
        const res = await fetch(
          'https://jsonplaceholder.typicode.com/users',
          { signal: controller.signal }
        );
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const data = await res.json();
        if (!controller.signal.aborted) setUsers(data);
      } catch (err) {
        if (!controller.signal.aborted) setError(err.message);
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    }
    loadUsers();
    return () => controller.abort();
  }, []);

  if (loading) return <p>Chargement…</p>;
  if (error) return <p role="alert">Chargement impossible : {error}</p>;
  if (users.length === 0) return <p>Aucun utilisateur.</p>;
  return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}

Axios : un client HTTP réutilisable

Axios transforme les réponses JSON et rejette par défaut les statuts hors de la plage 2xx. Contrairement à fetch, il nécessite une dépendance.

Un custom Hook pour charger les utilisateurs

import { useEffect, useState } from 'react';
import { getUsers } from './userService';

export function useUsers() {
  const [data, setData] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    getUsers(controller.signal)
      .then(users => {
        if (!controller.signal.aborted) setData(users);
      })
      .catch(err => {
        if (!controller.signal.aborted) setError(err.message);
      })
      .finally(() => {
        if (!controller.signal.aborted) setLoading(false);
      });
    return () => controller.abort();
  }, []);

  return { data, loading, error };
}

Le composant lit const { data, loading, error } = useUsers() et affiche le chargement, l’erreur, le résultat vide ou la liste. Ce Hook ne fournit ni cache partagé ni déduplication.

API : les réflexes à garder

  • Affichage : prévoir chargement, erreur et nouvel essai, résultat vide et succès.
  • Cycle de vie : annuler ou ignorer une réponse devenue inutile ; éviter les requêtes inutiles.
  • Cache : RTK Query ou TanStack Query gèrent le partage des données serveur ; un custom Hook seul ne crée pas de cache.
  • Secrets : garder les clés privées sur le serveur. Les variables injectées dans le frontend sont publiques.
  • CORS : l’autorisation d’une origine se configure sur le serveur ; no-cors ne rend pas une réponse lisible.
  • Diagnostic : consulter l’onglet Réseau, le statut HTTP et la réponse ; afficher un message utile sans exposer de données sensibles.

ECMAScript : le standard de JavaScript

  • ECMAScript est la spécification qui définit les règles et les fonctionnalités du langage.
  • JavaScript est l'implémentation la plus connue, utilisée dans les navigateurs et avec Node.js.
  • Le standard est maintenu par TC39, un comité qui fait évoluer le langage.

À retenir : ECMAScript décrit le langage ; JavaScript l'exécute dans un environnement.

2. Variables : let, const, var

const

Déclare une constante. NE PEUT être réassignée après initialisation. 

const PI = 3.14; 
// PI = 3.1415; <-- ERREUR

let

Déclare une variable avec une portée de bloc (`{}`). PEUT être réassignée. 

let compteur = 0;
compteur = 1;     // OK

var (À ÉVITER)

Déclare une variable avec une portée de fonction. Problèmes de portée (hoisting). 

if (true) {
  var x = 10;
}
// console.log(x); // 10 (Fuite hors du bloc)

⭐ Règle d'or : Toujours utiliser `const` par défaut. Si vous devez réassigner, utilisez `let`.

2. Types de Données Primitifs

  • String : Texte (ex: `"React"`).
  • Number : Nombres entiers et décimaux (ex: `10`, `3.14`).
  • Boolean : Vrai ou Faux (ex: `true`, `false`).
  • Null : Absence intentionnelle de valeur (ex: `let data = null;`).
  • Undefined : Variable déclarée mais non initialisée (valeur par défaut).
  • Symbol / BigInt : Utilisés pour des cas avancés.

Vérifier le type : 

let age = 30;
let nom = "Alice";
console.log(typeof age); // "number"
console.log(typeof nom); // "string"

3. Opérateurs de Comparaison

Double Égal (==) - Comparaison Lâche (Loose)

Compare la valeur en effectuant une conversion de type implicite. 

console.log(1 == '1');   // true
console.log(0 == false); // true
console.log(null == undefined); // true

Triple Égal (===) - Comparaison Stricte

Compare la valeur ET le type. Toujours utiliser === pour éviter les surprises. 

console.log(1 === '1');   // false
console.log(0 === false); // false
console.log(null === undefined); // false

Autres :

  • Arithmétiques : `+`, `-`, `*`, `/`, `%` (modulo), `**` (puissance).
  • Logiques : `&&` (ET), `||` (OU), `!` (NON).
  • Ternaire : `condition ? vrai : faux;` (pour les conditions simples).

4. Structures Conditionnelles

if / else if / else

Pour vérifier des conditions basées sur des expressions booléennes. 

const note = 85;
if (note > 90) {
  console.log("A");
} else if (note > 80) {
  console.log("B"); // C'est ici
} else {
  console.log("C");
}

switch / case

Pour vérifier si une variable correspond à plusieurs valeurs spécifiques. 

const jour = 'Lundi';
switch (jour) {
  case 'Samedi':
  case 'Dimanche':
    console.log("WE");
    break;
  default:
    console.log("Semaine");
}

Utilisez `switch` quand vous comparez une seule valeur à plusieurs constantes. Sinon, utilisez `if/else`.

5. Boucles : for, while

La boucle `for` (itération par index) 

// 1. Initialisation (let i = 0)
// 2. Condition de continuation (i < 5)
// 3. Incrémentation (i++)
for (let i = 0; i < 5; i++) {
  console.log("Tour " + i);
}

Boucles `while` et `do...while` 

// while : la condition est vérifiée avant chaque tour
let x = 0;
while (x < 3) {
  console.log("x est : " + x);
  x++;
}

// do...while : s'exécute au moins une fois
let y = 0;
do {
  console.log("y est : " + y);
} while (y > 0); // La boucle s'arrête après 1 tour

5. Boucles : for...of et for...in

for...of (Valeurs)

Itère sur les VALEURS d'objets itérables (tableaux, chaînes de caractères, etc.). 

const couleurs = ['rouge', 'vert', 'bleu'];
for (const couleur of couleurs) {
  console.log(couleur);
}
// Affiche : rouge, vert, bleu

for...in (Clés/Index)

Itère sur les CLÉS (propriétés) d'un objet. 

const voiture = { marque: 'BMW', annee: 2020 };
for (const cle in voiture) {
  console.log(cle + ' : ' + voiture[cle]);
}
// Affiche : marque : BMW, annee : 2020

Contrôle :

for (let i = 0; i < 10; i++) {
  if (i === 3) continue; // Passe au tour suivant
  if (i === 7) break;    // Arrête la boucle
  console.log(i);
}

6. Fonctions

Déclaration Classique

Blocs de code réutilisables qui peuvent prendre des paramètres et retourner une valeur (`return`). 

function addition(a, b = 1) { // b est un paramètre par défaut
  const resultat = a + b;
  return resultat;
  // Rien après return n'est exécuté
}

const somme = addition(5, 3); // 8
const unDePlus = addition(10); // 11 (b utilise sa valeur par défaut)

Fonctions Anonymes 

// Utilisée souvent comme argument (callback)
document.getElementById('btn').addEventListener('click', function() {
  console.log('Clic !'); 
});

6. Fonctions : Fléchées & Portée (Scope)

Fonctions Fléchées (Arrow Functions) - ES6

Syntaxe concise. N'a pas son propre `this` (très important en React). 

// Longue
const multiplication = (a, b) => {
  return a * b;
};

// Courte (return implicite pour une seule expression)
const carre = n => n * n;

Portée (Scope) des Variables

Le scope détermine où une variable est accessible. Scope de Bloc (avec `let`/`const`) est préférable. 

const globalVar = 'Globale';
function maFonction() {
  const localVar = 'Locale'; // Inaccessible à l'extérieur
  console.log(globalVar); 
}

7. Tableaux (Arrays)

Création et Accès

Les tableaux sont des listes ordonnées d'éléments (indexés à partir de 0). 

const legumes = ['carotte', 'tomate', 'oignon'];

console.log(legumes[0]);   // Accès : 'carotte'
console.log(legumes.length); // Propriété : 3

Mutations (Modification du tableau original)

  • `push(e)` : Ajoute un élément à la fin.
  • `pop()` : Retire le dernier élément.
  • `unshift(e)` : Ajoute un élément au début.
  • `shift()` : Retire le premier élément.
legumes.push('pomme de terre'); // ['carotte', ..., 'pomme de terre']

7. Tableaux : Méthodes de Transformation

Ces méthodes ne modifient pas le tableau original et sont essentielles en React (Programmation fonctionnelle).

.map()

Crée un nouveau tableau en appliquant une fonction à chaque élément. 

[1, 2].map(n => n * 2); 
// [2, 4]

.filter()

Crée un nouveau tableau avec les éléments qui passent un test (retournent `true`). 

[1, 2, 3].filter(n => n > 1);
// [2, 3]

.reduce()

Exécute une fonction sur chaque élément pour produire une seule valeur (accumulateur). 

[1, 2, 3].reduce((acc, n) => acc + n, 0); 
// 6

8. Objets

Création et Accès

Les objets sont des collections de paires clé/valeur non ordonnées (propriétés). 

const utilisateur = {
  nom: 'Dupont',
  age: 25,
  estActif: true,
  saluer: function() { return 'Bonjour ' + this.nom; }
};

// Accès 1 (dot notation)
console.log(utilisateur.nom);  // 'Dupont'

// Accès 2 (bracket notation, utile pour les clés dynamiques)
console.log(utilisateur['age']); // 25

Modification / Suppression 

utilisateur.age = 26; // Modifier
delete utilisateur.estActif; // Supprimer

8. Objets : Méthodes Utiles & Destructuring

Méthodes de Parcours 

Object.keys(utilisateur);   // ['nom', 'age', 'saluer']
Object.values(utilisateur); // ['Dupont', 26, function...]
Object.entries(utilisateur); // [['nom', 'Dupont'], ['age', 26], ...]

Destructuring (Démantèlement) - ES6

Extrait des valeurs d'un objet ou d'un tableau en variables distinctes. 

const { nom, age } = utilisateur;
console.log(nom); // 'Dupont'
console.log(age); // 26

const [premiere, ...reste] = [1, 2, 3];
console.log(premiere); // 1

Classes en JavaScript

Une classe est un modèle pour créer des objets partageant des propriétés et des méthodes. 

class Utilisateur {
  constructor(nom) {
    this.nom = nom;
  }

  saluer() {
    return `Bonjour ${this.nom}`;
  }
}

const user = new Utilisateur('Alice');
console.log(user.saluer()); // Bonjour Alice
  • constructor initialise l'instance.
  • new crée un objet à partir de la classe.
  • Les méthodes décrivent les comportements de l'objet.

Classes : héritage et réutilisation

extends permet de réutiliser une classe existante ; super() appelle son constructeur. 

class Admin extends Utilisateur {
  constructor(nom, role) {
    super(nom);
    this.role = role;
  }

  afficherRole() {
    return `${this.nom} : ${this.role}`;
  }
}

const admin = new Admin('Samir', 'formateur');

Les classes rendent le code objet plus lisible, tout en reposant sur les prototypes de JavaScript.

Qu'est-ce que le DOM ?

10. Événements : addEventListener

Qu'est-ce qu'un événement ?

Une action du navigateur ou de l'utilisateur (clic, survol, chargement, soumission de formulaire, touche enfoncée).

Attacher un écouteur 

const bouton = document.querySelector('#mon-bouton');

bouton.addEventListener('click', function(event) {
  console.log('Bouton cliqué !');
  // L'objet `event` contient des informations sur l'événement
  event.preventDefault(); // Empêche l'action par défaut (ex: soumission de formulaire)

  • Types fréquents : `click`, `submit`, `change`, `input`, `mouseover`, `keydown`.

10. Événements : Propagation & Délégation

Propagation (Bubbling)

Lorsqu'un événement se produit, il remonte du nœud cible vers la racine du DOM.

Délégation d'Événements

Attacher un seul écouteur à un élément parent pour gérer les événements de tous ses enfants (même ceux ajoutés dynamiquement). 

parent.addEventListener('click', function(e) {

11. ES6+ : écrire un JavaScript plus moderne

Template literals

Les backticks permettent d'insérer des expressions avec ${} et d'écrire du texte sur plusieurs lignes.

11. ES6+ : immutabilité et modules

Spread (...) : copier

Le spread décompose un tableau ou un objet. Il permet de créer une nouvelle valeur sans modifier l'originale.

const nombres = [1, 2];
const tous = [...nombres, 3];
const copie = [...nombres];

const user = { nom: 'Ali', actif: true };
const admin = { ...user, role: 'admin' };

Rest (...) : regrouper

Le rest rassemble les valeurs restantes dans un tableau ou un objet.

// math.js
function additionner(...nombres) {
  return nombres.reduce((total, n) => total + n, 0);
}

additionner(2, 3, 5); // 10

Les modules permettent de découper une grande application en fichiers spécialisés et reliés explicitement.

11. Modules : organiser le projet

Un module est un fichier JavaScript avec son propre espace de noms. Seules les valeurs exportées peuvent être utilisées par les autres fichiers.

Exporter

// math.js
export const PI = 3.14;

export function additionner(a, b) {
  return a + b;
}

export default function saluer(nom) {
  return `Bonjour ${nom}`;
}

Importer

// app.js
import saluer, { PI, additionner } from './math.js';

console.log(PI);                // 3.14
console.log(additionner(2, 3)); // 5
console.log(saluer('Lina'));
  • Export nommé : importé avec le même nom entre accolades.
  • Export par défaut : un seul par fichier ; le nom d'import peut changer.
  • Chemin relatif : ./ désigne le dossier actuel et ../ le dossier parent.

11. Modules : une structure de projet claire

Exemple de structure pour une application React :

src/
├── components/       # composants réutilisables
│   ├── Button.jsx
│   └── UserCard.jsx

Un fichier = un rôle

Le composant affiche, le service communique, l'utilitaire transforme.

Dépendances visibles

Les imports montrent ce dont chaque fichier a besoin.

Navigation simple

On retrouve rapidement le code sans fichier géant.

// services/api.js : une seule responsabilité
export async function getUsers() {

  if (!response.ok) throw new Error('Erreur API');
  return response.json();
}

// features/users/userUtils.js : logique réutilisable

Pourquoi c'est essentiel ?

  • Réutilisation : plusieurs composants peuvent importer la même fonction.

  • Équipe : chacun travaille sur des fichiers séparés avec moins de conflits.

12. Asynchrone : ne pas bloquer le programme

Synchrone, asynchrone et Event Loop

JavaScript exécute d'abord le code synchrone dans la Call Stack. Les tâches lentes, comme un minuteur ou une requête réseau, sont prises en charge par l'environnement puis replacées dans la file d'attente. L'Event Loop les récupère quand la pile est libre. 

console.log('1. Début');
setTimeout(() => console.log('3. Callback'), 0);
console.log('2. Suite du programme');
// 1. Début → 2. Suite du programme → 3. Callback

Pourquoi ?

Le navigateur ne laisse pas une requête réseau bloquer l'interface. Pendant l'attente, l'utilisateur peut continuer à interagir avec la page.

Callback

Une fonction passée en argument et exécutée plus tard lorsque l'opération est terminée.

Le problème des callbacks imbriqués

connexion(user, () => {
  chargerProfil(user, () => {
    chargerCommandes(user, () => {
      afficherResultat(); // difficile à maintenir
    });
  });
});

Les Promises puis async/await rendent cette logique plus lisible.

12. Promesses : .then(), async et await

Une Promise représente une opération en attente, réussie (fulfilled) ou échouée (rejected). Elle permet de chaîner les étapes et de centraliser les erreurs.

const promesse = new Promise((resolve, reject) => {
  const ok = true;
  if (ok) resolve('Données reçues');
  else reject(new Error('Erreur réseau'));
});

promesse
  .then(message => console.log(message))
  .catch(erreur => console.error(erreur));

Appeler une API avec .then()

fetch('/api/data')
  .then(response => {
    if (!response.ok) throw new Error('Erreur HTTP');
    return response.json();
  })
  .then(data => console.log(data))
  .catch(error => console.error(error))
  .finally(() => console.log('Terminé'));

La syntaxe async/await

Une fonction async retourne toujours une Promise. await attend son résultat sans bloquer le navigateur.

async function getData() {
  try {
    const response = await fetch('/api/data');
    if (!response.ok) throw new Error('Erreur HTTP');
    return await response.json();
  } catch (error) {
    console.error('Erreur :', error);
  }
}

// Plusieurs requêtes en parallèle
const resultats = await Promise.all([getData(), getData()]);
console.log(resultats);

Conseil : utilisez Promise.all() pour lancer des tâches indépendantes ensemble et gérez toujours les erreurs avec try/catch.

PARTIE 2 : NODE.JS

Exécuter JavaScript, utiliser npm et créer des scripts

Node.js : JavaScript en dehors du navigateur

Node.js permet d'exécuter JavaScript en dehors du navigateur, directement sur votre ordinateur ou sur un serveur.

Pourquoi Node.js ?

  • Exécuter des programmes JavaScript depuis le terminal.
  • Utiliser npm, le gestionnaire de paquets JavaScript.
  • Créer des scripts, des serveurs et des outils en ligne de commande.
  • Gérer les dépendances et les scripts d'un projet.

Navigateur vs Node.js

Le navigateur fournit le DOM et document. Node.js fournit le système de fichiers, le terminal et les outils serveur.

// navigateur
document.querySelector('h1');

// Node.js
console.log('Exécuté dans le terminal');

Installer Node.js et vérifier l'installation

  1. Ouvrir nodejs.org et choisir la version LTS.
  2. Exécuter l'installateur et conserver les options par défaut.
  3. Fermer puis rouvrir le terminal pour recharger le chemin système.

Vérifier les versions

node --version
npm --version

// Exemple de résultat :
// v22.x.x
// 10.x.x

Node.js installe généralement npm en même temps. Si une commande n'est pas reconnue, redémarrez le terminal ou vérifiez l'installation.

Node.js : créer et lancer un premier projet

# créer un dossier et initialiser npm
mkdir demo-node
cd demo-node
npm init -y

# créer app.js puis l'exécuter
node app.js

app.js

const nom = 'Lina';
console.log(`Bonjour ${nom}, Node.js fonctionne !`);

// Sortie dans le terminal :
// Bonjour Lina, Node.js fonctionne !

Ajouter une dépendance Node.js

npm install lodash

// package.json peut aussi contenir des scripts :
"scripts": {
  "start": "node app.js"
}

npm run start

Node.js fournit l'environnement d'exécution ; npm installe les paquets et lance les scripts du projet.

npm : le gestionnaire de paquets Node.js

npm signifie Node Package Manager. Il permet de télécharger, mettre à jour et supprimer des paquets JavaScript, puis de lancer les scripts du projet.

Commandes essentielles

npm init -y          # créer package.json
npm install          # installer les dépendances
npm install lodash   # ajouter un paquet
npm uninstall lodash # supprimer un paquet
npm run start        # lancer un script

npm registre

npm cherche les paquets dans le registre public. Chaque paquet contient du code réutilisable : bibliothèques, outils, plugins ou frameworks.

npm view lodash version
npm search date
npm outdated

npm automatise la gestion des dépendances : les versions sont enregistrées pour pouvoir reconstruire le projet.

package.json : la carte d'identité du projet

Ce fichier décrit le projet, ses commandes et les paquets dont il a besoin. Il est versionné avec le code et ne doit pas être supprimé.

{
  "name": "demo-node",
  "version": "1.0.0",
  "main": "app.js",
  "scripts": {
    "start": "node app.js",
    "test": "node --test"
  },
  "dependencies": {
    "lodash": "^4.17.21"
  },
  "devDependencies": {
    "nodemon": "^3.0.0"
  }
}
  • dependencies : paquets nécessaires pour exécuter l'application.
  • devDependencies : outils uniquement utiles pendant le développement.
  • scripts : raccourcis comme npm run start ou npm test.

node_modules et package-lock.json

node_modules/

Dossier qui contient le code réel des paquets installés et leurs propres dépendances.

  • Il peut devenir très volumineux.
  • On ne le commit généralement pas dans Git.
  • On le recrée avec npm install.

package-lock.json

npm y enregistre les versions exactes installées et l'arbre complet des dépendances.

# après avoir cloné le projet
npm install

# npm lit package-lock.json
# puis recrée node_modules

Règle importante : partager package.json et package-lock.json, mais ignorer node_modules.

Installer, mettre à jour et supprimer un paquet

# dépendance utilisée par l'application
npm install lodash

# outil uniquement pour le développement
npm install --save-dev nodemon

# mettre à jour selon package.json
npm update lodash

# supprimer un paquet et son entrée dans package.json
npm uninstall lodash

Après chaque commande

npm modifie package.json, met à jour package-lock.json et ajoute ou retire le paquet dans node_modules.

# voir les paquets installés
npm list --depth=0

# réinstaller proprement selon le lock
npm ci

npm ci est utile dans les pipelines de test et de déploiement, car il installe exactement les versions verrouillées.

Exemple : utiliser le paquet lodash

Lodash fournit des fonctions pratiques pour manipuler des tableaux et des objets. On l'installe une seule fois, puis on l'importe dans notre fichier.

# dans le terminal
npm install lodash
// app.js (CommonJS)
const _ = require('lodash');

const utilisateurs = [
  { nom: 'Lina', actif: true },
  { nom: 'Omar', actif: false },
  { nom: 'Sara', actif: true }
];

const actifs = _.filter(utilisateurs, { actif: true });
const noms = _.map(actifs, 'nom');
console.log(noms); // [ 'Lina', 'Sara' ]

Le paquet apporte une solution prête à l'emploi : on gagne du temps et on réduit le code répétitif.

PARTIE 3 : REACT

Développement d'Interface Utilisateur Moderne

13. Introduction à React

  • Qu'est-ce que React ? Une bibliothèque JS pour construire des interfaces utilisateur (UI) déclaratives.
  • Philosophie : "UI = f(état)". L'UI n'est qu'une fonction de l'état actuel de l'application.
  • Différences avec vanilla JS : React gère les mises à jour du DOM pour vous, vous vous concentrez sur la gestion de l'état.
  • Installation : Typiquement via des outils comme Vite ou Next.js (remplace Create React App).

Le Virtual DOM

Une représentation légère du DOM réel, gardée en mémoire par React. Les changements sont d'abord appliqués au V-DOM, puis React calcule les différences (diffing) et met à jour uniquement les parties nécessaires du DOM réel (minimisation des opérations coûteuses).

Approche moderne : créer React avec Vite

Vite est l'approche recommandée pour un nouveau projet : il démarre rapidement et fournit un serveur de développement moderne.

14. JSX : Syntaxe

Qu'est-ce que JSX ?

JavaScript XML. C'est une extension de syntaxe qui permet d'écrire du balisage HTML directement dans les fichiers JavaScript.

Règles et Expressions

  • Unique Parent : Tout le JSX retourné doit être enveloppé dans un seul élément parent (ou un `<></>`).

Composants React à classes : la structure

Avant les Hooks, on construisait les composants avec des classes JavaScript qui héritent de React.Component. Commençons par un composant simple, sans state.

import React from 'react';

class Bonjour extends React.Component {
  render() {
    return <h2>Bonjour {this.props.nom}</h2>;
  }
}

// Utilisation dans le composant parent
<Bonjour nom="Lina" />;
  • render() retourne le JSX affiché.
  • this.props lit les données envoyées par le parent.
  • Ce composant est prévisible : il affiche uniquement ses props.

Classes : introduire le state

Lire les props

class Bonjour extends React.Component {
  render() {
    return <h2>Bonjour {this.props.nom}</h2>;
  }
}

<Bonjour nom="Lina" />

Les props viennent du parent et sont en lecture seule.

Déclarer le state

class Compteur extends React.Component {
  constructor(props) {
    super(props);
    this.state = { compte: 0 };
  }

  incrementer = () => {
    this.setState(prevState => ({
      compte: prevState.compte + 1
    }));
  };
}

Le state contient les données internes et setState() demande un nouveau rendu.

Ne faites jamais this.state.compte++ directement : React ne sera pas informé correctement du changement.

Classes : cycle de vie et événements

Cycle de vie

componentDidMount() {
  this.timer = setInterval(() => {
    console.log('actif');
  }, 1000);
}

componentWillUnmount() {
  clearInterval(this.timer);
}

La première méthode se lance après le montage ; la seconde nettoie avant le démontage.

Une méthode classique peut perdre le contexte du composant. Une fonction fléchée ou bind(this) conserve le bon contexte.

  this.setState({ ouvert: true });
};

Ces composants sont importants pour maintenir du code ancien, même si les nouveaux composants utilisent surtout les fonctions et les Hooks.

17. State (État) : Le Hook useState

Qu'est-ce que l'État ?

Des données qui, lorsqu'elles changent, provoquent le re-rendu du composant (son actualisation dans le DOM).

useState Hook :

  • Retourne une paire : `[valeurActuelle, fonctionDeMiseÀJour]`.
  • La mise à jour du state est asynchrone.
import { useState } from 'react';

function Toggle() {
  const [isOn, setIsOn] = useState(false); // Valeur initiale: false

  const handleToggle = () => {
    // Utilisez une fonction de mise à jour pour des dépendances sûres
    setIsOn(prevIsOn => !prevIsOn);
  };

  return (
    <button onClick={handleToggle}>
      {isOn ? 'ON' : 'OFF'}
    </button>
  );
}

18. useEffect Hook : Effets de bord

Qu'est-ce qu'un Effet de Bord ?

Toute action qui interagit avec le monde extérieur à React (appels API, timers, manipulation directe du DOM, gestion des abonnements).

Tableau de Dépendances `[]`

  • `useEffect(() => { ... })` : S'exécute après chaque rendu.
  • `useEffect(() => { ... }, [])` : S'exécute seulement au montage (comme `componentDidMount`).
  • `useEffect(() => { ... }, [data])` : S'exécute au montage et quand `data` change. 
useEffect(() => {
  fetchData(); // Appel API
}, []); // Se lance une seule fois (après le 1er rendu)

18. useEffect : La Fonction de Nettoyage (Cleanup)

Pourquoi ?

Pour annuler ou nettoyer les effets qui persistent après que le composant ait été retiré du DOM (démontage) ou avant que l'effet ne s'exécute à nouveau.

Exemple : Timer

useEffect(() => {
  const timer = setInterval(() => {
    console.log('Tick');
  }, 1000);

  // Fonction de nettoyage
  return () => {
    clearInterval(timer); // Arrête le timer
    console.log("Cleanup effectuée");
  };
}, []);

Le `return` est essentiel pour éviter les fuites de mémoire (memory leaks).

  • Nommage : Les gestionnaires d'événements sont en camelCase (ex: `onClick`, `onChange`).
  • Fonction Passée : On passe une fonction, pas une chaîne de caractères (`onClick={handleClick}`).
  • Synthetic Events : React enveloppe les événements natifs dans un objet appelé `SyntheticEvent` qui assure une compatibilité multi-navigateurs.

Passer des Arguments 

function List() {
  const itemId = 5;
  // Utiliser une fonction fléchée inline pour passer un argument

      Supprimer l'item 5

}

21. Formulaires Contrôlés

Le Contrôle par React

Un formulaire est "contrôlé" lorsque sa valeur est gérée par le state de React. 

import { useState } from 'react';

function Formulaire() {
  const [valeur, setValeur] = useState('');

  const handleChange = (event) => {
    // La valeur de l'input est toujours lue depuis l'objet event
    setValeur(event.target.value); 
  };

  return (
    <input 
      type="text" 
      value={valeur} // La valeur affichée est lue depuis le state
      onChange={handleChange} // Chaque frappe met à jour le state
      placeholder="Votre nom"
    />
  );
}

C'est le pattern standard pour la gestion des inputs en React.

29. Hook useReducer : gérer des états complexes

useReducer est une alternative à useState pour les états plus complexes (objets, multiples sous-valeurs) ou avec beaucoup de transitions.

  • Basé sur le pattern state + action → nouveau state.
  • Ressemble beaucoup à Redux (même logique de reducer).
import { useReducer } from "react";

function reducer(state, action) {
  switch (action.type) {
    case "increment":
      return { count: state.count + 1 };
    case "decrement":
      return { count: state.count - 1 };
    case "reset":
      return { count: 0 };
    default:
      return state;
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });

  return (
    <div>
      <p>Compteur : {state.count}</p>
      <button onClick={() => dispatch({ type: "increment" })}>+</button>
      <button onClick={() => dispatch({ type: "decrement" })}>-</button>
      <button onClick={() => dispatch({ type: "reset" })}>Reset</button>
    </div>
  );
}

Très utile pour des formulaires complexes, des wizards, ou des composants avec beaucoup de règles métier.

30. Custom Hooks : réutiliser la logique

Un custom hook est une fonction qui commence par use... et qui permet de factoriser de la logique React (state, effets, contexte) pour la réutiliser dans plusieurs composants.

  • Permet d’éviter les duplications (DRY).
  • Peut combiner plusieurs hooks internes (useState, useEffect…).

Exemple : hook useToggle 

import { useState } from "react";

function useToggle(initialValue = false) {
  const [value, setValue] = useState(initialValue);
  const toggle = () => setValue((prev) => !prev);
  return { value, toggle };
}

// Utilisation
function Switch() {
  const { value: isOn, toggle } = useToggle();

  return (
    <button onClick={toggle}>
      {isOn ? "ON" : "OFF"}
    </button>
  );
}

Plus tard, on peut créer des custom hooks pour les appels API (useFetch, useAuth, etc.).

31. React Router DOM : Introduction

React Router DOM permet de gérer la navigation entre plusieurs pages dans une application Single Page Application (SPA) sans rechargement complet du navigateur.

PARTIE 5 : REDUX PRATIQUE

État global, Redux classique, Toolkit et custom hooks

Pourquoi l'état global devient un problème ?

Un état est global lorsqu'il doit être lu ou modifié par plusieurs composants éloignés dans l'application.

Exemples

  • Utilisateur connecté et permissions.
  • Panier et nombre d'articles.
  • Thème clair/sombre.
  • Notifications et messages non lus.

Sans organisation

Chaque composant peut garder sa propre copie. Une modification dans un endroit peut alors ne pas être reflétée ailleurs.

Navbar : user = "Lina"
Profile : user = "Lina"
Cart    : user = "Lina"
// Plusieurs copies à synchroniser

Le problème n'est pas useState : c'est le partage et la synchronisation d'une même donnée.

Le prop drilling : faire passer des données trop loin

Le prop drilling arrive lorsqu'une donnée doit traverser plusieurs composants intermédiaires qui ne l'utilisent pas, uniquement pour atteindre un composant final.

function App() {
  const user = { name: 'Lina' };
  return <Layout user={user} />;
}

function Layout({ user }) {
  return <Header user={user} />;
}

function Header({ user }) {
  return <UserMenu user={user} />;
}

function UserMenu({ user }) {
  return <span>Bonjour {user.name}</span>;
}

Couplage

Les composants intermédiaires connaissent des données qui ne les concernent pas.

Maintenance

Ajouter une nouvelle donnée oblige à modifier toute la chaîne.

Lisibilité

Il devient difficile de savoir qui possède et modifie la donnée.

Ce que Redux corrige

Redux place l'état partagé dans un store unique. Les composants lisent ce store et demandent un changement en envoyant une action.

Store

une source unique

Action

une intention

Reducer

une transition prévisible

UI

mise à jour automatique

const count = useSelector(state => state.counter.value);
const dispatch = useDispatch();

// Le composant ne modifie pas le store directement
dispatch({ type: 'counter/increment' });
  • Centralisation : une seule valeur partagée au lieu de copies concurrentes.
  • Traçabilité : chaque modification correspond à une action identifiable.
  • Prévisibilité : les reducers décrivent comment l'état peut évoluer.

Redux classique : comprendre le flux

Redux est une bibliothèque qui centralise l'état de l'application dans un store. Les composants ne modifient pas directement cet état.

UI

affiche le state

Action

décrit l'intention

Reducer

calcule le nouvel état

Store

conserve le state

// Une action est un objet descriptif
{ type: 'counter/increment', payload: 1 }

// Un reducer est une fonction pure
function reducer(state, action) {
  if (action.type === 'counter/increment') {
    return { count: state.count + action.payload };
  }
  return state;
}

Flux unidirectionnel : UI → dispatch(action) → reducer → nouveau state → UI.

Redux classique : créer le store et le reducer

Le store contient l'état global. dispatch() envoie une action ; getState() lit l'état ; subscribe() réagit à ses changements.

import { createStore } from 'redux';

const initialState = { count: 0 };

function counterReducer(state = initialState, action) {
  switch (action.type) {
    case 'INCREMENT':
      return { ...state, count: state.count + 1 };
    case 'ADD':
      return { ...state, count: state.count + action.payload };
    case 'RESET':
      return initialState;
    default:
      return state;
  }
}

const store = createStore(counterReducer);
store.dispatch({ type: 'ADD', payload: 5 });
console.log(store.getState()); // { count: 5 }
  • Le reducer ne modifie jamais directement state : il retourne un nouvel objet.
  • Le switch associe chaque type d'action à une transition d'état.
  • Une action ne fait rien seule : elle doit être envoyée avec dispatch().

Redux classique : connecter le store à React

Le package react-redux fournit Provider pour rendre le store disponible et les fonctions useSelector/useDispatch pour le lire et envoyer des actions.

import { Provider, useSelector, useDispatch } from 'react-redux';
import { store } from './store';

function Counter() {
  const count = useSelector(state => state.count);
  const dispatch = useDispatch();

  return (
    <button onClick={() => dispatch({ type: 'INCREMENT' })}>
      Compteur : {count}
    </button>
  );
}

// main.jsx
<Provider store={store}>
  <Counter />
</Provider>

Cette approche fonctionne, mais elle demande beaucoup de code répétitif : actions, types, switch, reducers et configuration manuelle.

36. Redux Toolkit : Introduction

Redux Toolkit (RTK) simplifie la gestion de l’état global en éliminant la complexité du Redux classique.

  • Problème : Redux classique est verbeux (actions, switch...).
  • Solution : RTK fournit createSlice() & configureStore().
  • Permet de partager un état global entre plusieurs composants.
npm install @reduxjs/toolkit react-redux

⭐ Recommandé officiellement par l’équipe Redux.

37. Configuration complète de Redux Toolkit

1️⃣ Créer un Slice

// src/features/counterSlice.js
import { createSlice } from "@reduxjs/toolkit";

export const counterSlice = createSlice({
  name: "counter",
  initialState: { value: 0 },
  reducers: {
    increment: (state) => { state.value += 1 },
    decrement: (state) => { state.value -= 1 },
    reset: (state) => { state.value = 0 },
  },
});

export const { increment, decrement, reset } = counterSlice.actions;
export default counterSlice.reducer;

Redux Toolkit : moins de code, plus de sécurité

Redux Toolkit (RTK) est la façon moderne d'écrire Redux. Il garde le même flux, mais génère les actions, simplifie les reducers et configure le store.

createSlice

Crée le reducer et les action creators ensemble.

configureStore

Configure le store avec de bons réglages par défaut.

Immer

Autorise une syntaxe de mutation sûre dans les reducers.

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment(state) {
      state.value += 1; // Immer produit un nouvel état immuable
    }
  }
});

// RTK génère automatiquement cette action
dispatch(counterSlice.actions.increment());

RTK ne remplace pas les concepts Redux : il les rend plus simples à appliquer correctement.

Redux Toolkit : appels API avec createAsyncThunk

createAsyncThunk encapsule une opération asynchrone et génère automatiquement trois actions : pending (en cours), fulfilled (réussite) et rejected (erreur).

import { createAsyncThunk } from '@reduxjs/toolkit';

export const fetchUsers = createAsyncThunk(
  'users/fetchUsers',
  async (_, thunkAPI) => {
    try {
      const response = await fetch('/api/users');
      if (!response.ok) throw new Error('Erreur serveur');
      return await response.json();
    } catch (error) {
      return thunkAPI.rejectWithValue(error.message);
    }
  }
);

Le composant fait seulement dispatch(fetchUsers()). Le thunk gère l'appel réseau et transmet le résultat au slice.

createAsyncThunk : charger, réussir, échouer

const usersSlice = createSlice({
  name: 'users',
  initialState: { data: [], status: 'idle', error: null },
  reducers: {},
  extraReducers: builder => {
    builder
      .addCase(fetchUsers.pending, state => {
        state.status = 'loading';
        state.error = null;
      })
      .addCase(fetchUsers.fulfilled, (state, action) => {
        state.status = 'succeeded';
        state.data = action.payload;
      })
      .addCase(fetchUsers.rejected, (state, action) => {
        state.status = 'failed';
        state.error = action.payload || action.error.message;
      });
  }
});

pending

Afficher un loader.

fulfilled

Afficher les données.

rejected

Afficher un message d'erreur.

Ce modèle évite les états incohérents et centralise toute la logique API dans le slice.

Redux pratique : gérer un utilisateur connecté

Un cas concret d'état global : plusieurs composants doivent connaître l'utilisateur sans se transmettre ses données par props.

const authSlice = createSlice({

  initialState: { user: null, isAuthenticated: false },
  reducers: {
    login(state, action) {
      state.user = action.payload;
      state.isAuthenticated = true;

    logout(state) {
      state.user = null;
      state.isAuthenticated = false;
    }
  }

  • Login modifie le store.
  • Navbar lit le même utilisateur.
  • logout remet l'état à sa valeur initiale.

Redux pratique : créer des custom hooks

Un custom hook masque la répétition et donne une API claire aux composants. Le composant n'a plus besoin de connaître les chemins internes du store.

// hooks/reduxHooks.js
import { useDispatch, useSelector } from 'react-redux';
import { login, logout } from '../features/auth/authSlice';

export const useAppDispatch = () => useDispatch();
export const useCurrentUser = () =>
  useSelector(state => state.auth.user);
export const useIsAuthenticated = () =>
  useSelector(state => state.auth.isAuthenticated);

export function useAuthActions() {
  const dispatch = useAppDispatch();
  return {
    login: user => dispatch(login(user)),
    logout: () => dispatch(logout())
  };
}
// Navbar.jsx
const user = useCurrentUser();
const { logout } = useAuthActions();

return user ? <button onClick={logout}>Quitter</button> : null;

Les composants consomment une intention métier : logout(), pas un détail technique de Redux.

Redux pratique : règles pour un projet solide

  • Stocker l'état partagé : auth, panier, filtres globaux, cache API.
  • Garder l'état local : ouverture d'un menu ou valeur temporaire d'un formulaire.

PARTIE 6 : APIs & Intégration Back-End

REST, HTTP, JSON, Fetch, Axios & bonnes pratiques

41. Qu’est-ce qu’une API ? Qu’est-ce qu’une REST API ?

Une API (Application Programming Interface) est une porte d’entrée permettant à un programme d’en appeler un autre pour récupérer ou envoyer des données.

  • API Web : accessible via HTTP(s), généralement au format JSON.
  • REST (REpresentational State Transfer) : style d’API qui utilise les verbes HTTP et des URLs pour manipuler des ressources.
  • Une ressource peut être : /users, /orders, /products, etc.

Exemple : GET https://api.example.com/users/42 → récupère l’utilisateur avec l’ID 42.

42. Verbes HTTP & Codes de Statut

Verbes principaux

  • GET : Lire / récupérer des données.
  • POST : Créer une nouvelle ressource.
  • PUT : Remplacer complètement une ressource.
  • PATCH : Modifier partiellement une ressource.
  • DELETE : Supprimer une ressource.

Codes de statut HTTP (réponse serveur)

  • 2xx : Succès (200 OK, 201 Created).
  • 4xx : Erreur côté client (400 Bad Request, 401 Unauthorized, 404 Not Found).
  • 5xx : Erreur côté serveur (500 Internal Server Error).

Toujours vérifier le code de statut avant de traiter la réponse JSON.

43. Endpoints, Headers, Body & JSON

1️⃣ Endpoint

URL d’un service précis, par exemple : https://api.example.com/users?page=2.

2️⃣ Headers

Métadonnées envoyées avec la requête/réponse :

  • Content-Type: application/json
  • Authorization: Bearer <token>

3️⃣ Body (corps)

Données envoyées dans une requête (POST/PUT/PATCH), souvent en JSON. 

// Exemple de payload JSON
{
  "name": "Alice",
  "email": "alice@example.com"
}

JSON = JavaScript Object Notation : format léger, lisible, idéal pour le Web.

44. Intégrer une API avec fetch()

fetch est l’API native du navigateur pour faire des requêtes HTTP.

Exemple : GET + gestion du chargement / erreur 

import { useEffect, useState } from "react";

function Users() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    async function loadUsers() {
      try {
        const res = await fetch("https://jsonplaceholder.typicode.com/users");

        if (!res.ok) {
          throw new Error("Erreur HTTP : " + res.status);
        }

        const data = await res.json();
        setUsers(data);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    }

    loadUsers();
  }, []);

  if (loading) return <p>Chargement...</p>;
  if (error) return <p>Erreur : {error}</p>;

  return (
    <ul>
      {users.map((u) => (
        <li key={u.id}>{u.name}</li>
      ))}
    </ul>
  );
}

45. Axios : bibliothèque HTTP

Axios est une bibliothèque populaire pour simplifier les appels HTTP. Elle fonctionne dans le navigateur et dans Node.js.

Installation

npm install axios

Exemple simple

import axios from "axios";
import { useEffect, useState } from "react";

function Posts() {

  useEffect(() => {
    axios
      .get("https://jsonplaceholder.typicode.com/posts")

  return (
    <ul>
      {posts.slice(0, 5).map((p) => (
        <li key={p.id}>{p.title}</li>
      ))}

46. Bonnes pratiques pour l’intégration API

  • 📦 Isoler la logique API dans des services ou custom hooks (useApi, useUsers…).
  • 🧠 Toujours gérer les états : loading, error, data.
  • 🔐 Ne jamais mettre de secrets (token privé, clé API sensible) dans le front. Utiliser un back-end ou des variables d’environnement côté serveur.
  • 🧪 Logguer les erreurs (console, Sentry, etc.) et afficher un message clair à l’utilisateur.
  • ♻️ Utiliser des custom hooks + Redux/RTK Query ou TanStack Query pour la mise en cache et la synchronisation serveur.

Exemple de custom hook simple avec Axios 

import { useEffect, useState } from "react";
import { api } from "./apiClient";

function useUsers() {
  const [data, setData] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    api
      .get("/users")
      .then((res) => setData(res.data))
      .catch((err) => setError(err.message))
      .finally(() => setLoading(false));
  }, []);

  return { data, loading, error };
}
